# NEO Tracker

[![CI](https://github.com/apshonkin/nasa-neo-tracker/actions/workflows/ci.yml/badge.svg)](https://github.com/apshonkin/nasa-neo-tracker/actions/workflows/ci.yml)

Приложение на Yii2, которое показывает сближения астероидов с Землёй по данным NASA.
Есть каталог с фильтрами, картинка дня и сбор донатов на "остановку астероида".

Стек: PHP 8.3, Yii2 2.0.55, PostgreSQL 17, Redis 7, Bootstrap 5.

## Что есть

- Каталог сближений из NeoWs. Фильтр по названию и по опасным объектам, сортировка по дате,
  расстоянию, скорости и размеру. Прошедшие сближения не показываются.
- Картинка дня (APOD). Если NASA не отвечает, показывается последняя сохранённая.
- Донаты через фейковый платёжный шлюз и статистика по ним.
- Вход и регистрация, роли `user` и `admin` на RBAC. Статистика донатов доступна только админу.

## Требования

- PHP 8.3+ с расширениями `pdo_pgsql`, `curl`, `openssl`
- PostgreSQL 13+
- Redis 6+ (расширение `ext-redis` не нужно, `yii2-redis` работает без него)
- Composer 2

## Запуск в Docker

Нужны только Docker с Compose и make.

```bash
make init
```

Команда создаст `.env` из `.env.example` (секрет для кук сгенерируется сам), соберёт образ,
поднимет контейнеры, поставит зависимости и применит миграции. Дальше открыть http://localhost:8899

Что поднимается:

| Сервис | Что делает |
|---|---|
| `nginx` | отдаёт статику, PHP передаёт в php-fpm. Видит только `web/` |
| `php` | php-fpm 8.3 с кодом проекта |
| `cron` | тот же образ, по расписанию загружает данные из NASA |
| `postgres` | PostgreSQL 17, данные в томе `pgdata` |
| `redis` | Redis 7 как чистый кеш, без сохранения на диск |

Остальные команды — `make help`: `make logs`, `make sh`, `make psql`, `make check` (стиль, phpstan
и тесты внутри контейнера), `make destroy` (остановить и удалить базу).

`GET /health` отвечает 200, если доступны база и Redis, и 503, если нет.

Образ собирается в несколько этапов из одного `docker/php/Dockerfile`: `dev` для разработки
(код монтируется с диска, есть composer) и `prod` (код и зависимости внутри, без dev-пакетов,
OPcache не проверяет файлы, процесс не от root). Прод-образ собирается в CI: `make build-prod`.

## Установка без Docker

```bash
composer install
```

Создать базу и пользователя:

```bash
sudo -u postgres psql \
  -c "CREATE ROLE neo_tracker LOGIN PASSWORD 'neo_tracker' CREATEDB" \
  -c "CREATE DATABASE neo_tracker OWNER neo_tracker"
```

Скопировать локальный конфиг и прописать в нём доступы к базе, секрет для кук и ключ NASA:

```bash
cp config/local.php.example config/local.php
php -r "echo bin2hex(random_bytes(16)), PHP_EOL;"   # это для cookieValidationKey
$EDITOR config/local.php
```

`config/local.php` в git не коммитится. Если его нет, приложение не запустится и напишет, что делать.

Миграции и запуск:

```bash
php yii migrate --interactive=0
php yii serve --port=8899 --docroot=web
```

Дальше открыть http://localhost:8899

Миграции сразу создают тестовые данные и два аккаунта: `admin` / `admin` и `user` / `user`.

### Ключ NASA

По умолчанию стоит `DEMO_KEY`, но у него лимит около 10 запросов в час с одного IP.
Посмотреть хватит, загрузить данные нормально уже нет. Свой ключ бесплатный, берётся на
[api.nasa.gov](https://api.nasa.gov/) и прописывается в `config/local.php`.

## Загрузка данных

```bash
php yii nasa/apod                              # картинка дня
php yii nasa/asteroids                         # сближения на 7 дней вперёд
php yii nasa/asteroids 2026-09-01 2026-09-07   # за свои даты
```

На сервере обе команды надо поставить в крон. Строки для крона есть в `commands/NasaController.php`:
картинку дня проверяем раз в полчаса, потому что NASA выкладывает её в разное время,
а астероиды раз в сутки ночью, чаще там ничего не меняется.

## Конфиги

| Файл | Что там | В git |
|---|---|---|
| `config/web.php`, `config/console.php` | сборка конфига приложения | да |
| `config/db.php` | подключение к PostgreSQL | да, без паролей |
| `config/redis.php` | подключение к Redis | да |
| `config/params.php` | параметры и значения по умолчанию | да |
| `config/local.php` | доступы к базе, секрет кук, ключ NASA | нет |
| `config/local.php.example` | пример для local.php | да |
| `config/phpstan-config.php` | список компонентов для phpstan | да |
| `.env` | настройки для Docker | нет |
| `.env.example` | пример для .env | да |

Доступы к базе и Redis, ключ NASA и секрет кук читаются из переменных окружения
(`DB_HOST`, `NASA_API_KEY`, `COOKIE_VALIDATION_KEY` и т.д.), а без них берутся значения
по умолчанию для локального запуска. `local.php` мержится поверх через `ArrayHelper::merge`,
так что в нём можно переопределить любой компонент. В Docker вместо него подставляется
пустой `docker/php/local.php`: там все настройки из окружения.

## Почему сделано так

**Если NASA лежит, сайт не падает.** Картинка дня сначала берётся из своей базы, потом из API,
а если API не ответило, показывается последняя сохранённая. Лучше вчерашняя картинка,
чем ошибка на главной.

**Повторяем запрос не всегда.** `NasaClient` повторяет запрос только при сетевой ошибке и 5xx,
до трёх раз с паузой. На 4xx повторять бесполезно, там ошибка в параметрах. На 429 тоже:
лимит кончился, и повторы только сожгут остаток. Ограничение NeoWs в 7 дней на запрос
проверяется ещё до обращения к API, чтобы не тратить лимит зря.

**Синхронизацию можно запускать сколько угодно раз.** Одно и то же сближение приходит от NASA
несколько дней подряд, и расстояние в нём уточняется. Поэтому `upsert`, а не `insert`,
и всё в одной транзакции: сохранилось либо всё, либо ничего.

**Оплату подтверждает шлюз.** Донат записывается в базу до перехода к оплате, чтобы шлюзу было
куда возвращать пользователя. Но оплаченным он становится только после ответа шлюза,
потому что страницу возврата можно открыть руками и ничего не платить. Шлюз спрятан
за `PaymentGatewayInterface`, сейчас там `FakePaymentGateway`, заменить его можно одной строкой
в конфиге контейнера.

**У кеша свой префикс.** Redis на сервере может быть общим, поэтому ключи этого приложения
начинаются с `neo:`. В кеше лежит структура таблиц и роли RBAC, чтобы не читать их из базы
на каждый запрос.

**Топ донатов лежит в кеше и сбрасывается при оплате.** Топ считается по всем оплаченным
донатам сразу (`sum` и `group by`), а меняется только когда кто-то заплатил. Поэтому он
кешируется в Redis с тегом `donations`, а `Donation::markPaid()` этот тег сбрасывает.
Это единственное место, где донат становится оплаченным, так что пропустить сброс нельзя.
Срок жизни у кеша час, это на случай, если данные поменяют в базе руками.
Последние донаты не кешируются: там простой запрос по индексу на `paid_at` с `limit 10`,
кеш ничего не ускорит.

**Секретов нет в репозитории.** Всё лежит в `config/local.php`, который в `.gitignore`.

## Проверки

```bash
composer test     # тесты (Codeception)
composer static   # phpstan, уровень 8
composer cs       # проверка стиля (стандарт Yii2, он же PSR-12)
composer cs-fix   # поправить стиль автоматически
```

phpstan стоит на 8 уровне с расширением для Yii2, без baseline и без `@phpstan-ignore`.

Тесты покрывают `NasaClient`: где он повторяет запрос, а где нет. Сеть в тестах не нужна,
вместо curl подставляются заранее заданные ответы.

Всё это гоняется в GitHub Actions на каждый пуш в `main` и на пул-реквесты.

## Структура

```
commands/     консольные команды, загрузка данных из NASA
components/   клиент NASA и платёжный шлюз
services/     логика: картинка дня, астероиды, донаты
models/       модели, формы, модели поиска
controllers/  контроллеры, логики в них почти нет
views/        шаблоны
migrations/   миграции и тестовые данные
tests/        тесты
```

